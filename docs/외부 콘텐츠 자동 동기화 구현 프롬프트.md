# 외부 콘텐츠 자동 동기화 구현 프롬프트

이 파일은 `게시글 자동 배치 개선안.md`의 실행용 프롬프트만 모아 둔다. 설계·정책·완료 조건의 기준은 개선안이며, 두 문서가 다르면 개선안을 우선한다.

## 사용 순서

1. 아래 1차 프롬프트로 `workflow_dispatch` 전용 구현과 수동 검증을 완료한다.
2. 실제 신규 콘텐츠 1건의 `master` 커밋과 Cloudflare Production 반영을 확인한다.
3. 아래 2차 프롬프트로 별도 커밋에서 매시간 schedule을 활성화한다.
4. 네이버 매물 프롬프트는 승인된 원본 API·CSV·export 경로가 확인된 뒤에만 사용한다.

---

## 1차 프롬프트: 수동 실행 전용 구현

```text
리더스시티 행복한부동산 홈페이지 저장소에 공식 네이버 블로그와 공식 YouTube 채널의 외부 콘텐츠 자동 동기화를 구현해줘.

이 작업의 기준 문서는 docs/게시글 자동 배치 개선안.md다. 문서를 처음부터 끝까지 읽고, 특히 확정 운영 정책·실행 주기·출처 검증·실패 정책·구현 단계·완료 조건을 그대로 지켜라. 이 프롬프트와 설계 문서가 다르면 설계 문서를 우선한다.

작업 시작 전:
- 원격 default branch와 최신 SHA를 확인한다.
- CODEX.md와 그 문서가 지정한 핵심 기획서·설계서·체크리스트를 읽는다.
- package.json, external-links.json, content-validation.mjs, import-content-assets.mjs, src/lib/content.ts, ExternalContentList.astro, 관리자 외부 링크 편집 코드, worker 허용 경로, tests, ci.yml, wrangler.jsonc를 실제 코드 기준으로 분석한다.
- 관련 없는 사용자 변경을 보존한다.

범위:
- 네이버 RSS에 노출되는 공식 블로그 신규 글 감지
- 공식 YouTube 채널의 공개 영상 감지
- external-links.json 신규 항목 append-only 병합
- 자체 WebP 썸네일 준비와 thumbnail:null fallback
- dry-run, 테스트, workflow_dispatch 전용 GitHub Actions
- .github/automation-health.json과 45일 keepalive 로직
- 관련 핵심 문서와 운영 가이드 동기화

확정 운영 정책:
- 공식 블로그·YouTube 신규 항목은 published로 자동 추가한다.
- 검증 성공 시 master에 직접 push한다.
- 1차 구현에는 schedule을 넣지 말고 workflow_dispatch만 둔다.
- schedule은 수동 실행과 Cloudflare Production 배포 검증 후 별도 2차 커밋에서 추가한다.
- 네이버페이 부동산 페이지·비공개 API·브라우저 자동화 크롤링은 구현하지 않는다.

네이버 블로그:
- 공식 블로그 ID p5468300과 HTTPS RSS를 사용한다.
- 목표는 RSS에 노출되는 공식 신규 글 감지다.
- 외부 보내기 허용이 꺼져 RSS에 없는 글은 자동 감지한다고 표현하지 않는다.
- ID는 naver-blog-{logNo}, 제목·URL·게시일은 공식 메타데이터를 사용한다.
- summary는 AI 호출 없이 결정론적 기본 문구로 만든다.
- 기존 summary/status/thumbnail을 덮어쓰지 않는다.

YouTube:
- YouTube Data API v3와 승인된 고정 channelId를 사용한다.
- channels.list(contentDetails)에서 uploads playlist를 얻고 playlistItems.list(part=snippet,contentDetails,status)를 사용한다.
- publishedAt에는 snippet.publishedAt이 아니라 contentDetails.videoPublishedAt을 저장한다.
- status.privacyStatus가 public이고 snippet.videoOwnerChannelId가 승인 channelId와 같은 항목만 허용한다.
- contentDetails.videoId와 watch URL을 일치시킨다.
- 기존 내부 ID가 있으면 URL의 원본 videoId도 비교하고, 정규화 ID는 같지만 원본 videoId가 다르면 전체 동기화를 실패시킨다.
- 기존 항목을 자동 삭제하거나 수동 수정값을 덮어쓰지 않는다.
- YOUTUBE_API_KEY는 GitHub Actions Secret으로만 사용하고 로그에 출력하지 않는다.

썸네일과 장애 처리:
- 공식 허용 HTTPS 호스트, 2xx, Content-Type, 최대 바이트, 디코딩, 해상도를 검증하고 WebP 재인코딩으로 메타데이터를 제거한다.
- 썸네일만 실패하면 경고 후 thumbnail:null로 항목을 추가한다.
- 출처·호스트·채널 불일치, ID 충돌, 파싱 오류, JSON 검증 오류는 전체 동기화를 중단한다.
- 기존 UI의 null fallback을 테스트로 고정한다.
- sharp를 사용하면 직접 의존성으로 명시하고 transitive dependency에 기대지 않는다.

동기화 특성:
- 같은 입력으로 두 번 실행하면 두 번째 diff가 없어야 한다.
- 임시 데이터 생성·검증 후 최종 파일을 교체하고, 실패 시 기존 JSON·이미지를 손상시키지 않는다.
- package.json에 sync:external과 sync:external:dry-run 명령을 추가한다.
- dry-run은 외부 조회·diff·검증만 수행하고 작업트리를 바꾸지 않는다.
- JSON 전체 재정렬 같은 불필요한 diff를 만들지 않는다.

GitHub Actions 1차 구현:
- 새 sync-external-content.yml은 workflow_dispatch만 지원한다.
- contents:write는 이 워크플로에만 둔다.
- concurrency와 timeout을 설정한다.
- npm ci, sync, npm test, npm run check, npm run build를 수행한다.
- GITHUB_TOKEN push가 기존 push 기반 ci.yml을 재실행하지 않으므로 이 검사를 생략하지 않는다.
- 콘텐츠 커밋은 git add -- src/data/external-links.json public/images/blog/ public/images/youtube/만 사용한다.
- keepalive 커밋은 git add -- .github/automation-health.json만 사용한다.
- allowlist 밖의 작업트리 변경이 있으면 커밋하지 말고 실패시킨다.
- git add -A, git add ., 빈 커밋을 사용하지 않는다.
- 콘텐츠 커밋 메시지는 chore(content): sync external content, keepalive는 chore(automation): refresh scheduler activity를 사용한다.
- .github/automation-health.json의 lastKeepaliveAt으로 45일 경계를 관리한다.
- 콘텐츠 변경이 없고 45일 미만이면 무변경 종료, 45일 이상이면 상태 파일만 갱신한다.

테스트:
- 개선안 14장의 모든 테스트를 구현한다.
- 외부 HTTP는 fixture 또는 주입 가능한 fetch/clock으로 결정론적으로 테스트한다.
- YouTube 공개 시각, 공개 상태, 승인 채널, 원본 videoId 충돌을 각각 검증한다.
- 썸네일 단독 실패와 신뢰 경계 실패를 분리해 검증한다.
- 45일 전·경계·이후와 stage 허용 경로를 검증한다.

검증:
- npm ci
- npm test
- npm run check
- npm run build
- npx wrangler deploy --dry-run
- workflow_dispatch 수동 실행
- 실제 신규 콘텐츠 1건의 master 커밋
- Cloudflare 새 Production 빌드와 leaderscityhappy.com 반영

로컬 검사까지만 가능한 경우 schedule을 추가하지 말고, 수동 실행·Cloudflare 확인이 남았다고 명확히 보고한다. 실행하지 않은 검사는 통과했다고 쓰지 않는다.

완료 보고는 CODEX.md 형식을 따르고 변경 파일, 데이터 경계, 실패 정책, 테스트 실제 결과, Cloudflare 확인, 미완료 항목을 포함한다.
```

## 2차 프롬프트: 매시간 schedule 활성화

```text
외부 콘텐츠 자동 동기화 1차 구현의 수동 검증 결과를 확인하고, 조건을 모두 충족한 경우에만 매시간 예약 실행을 별도 커밋으로 활성화해줘.

기준 문서:
- docs/게시글 자동 배치 개선안.md
- docs/외부 콘텐츠 자동 동기화 구현 프롬프트.md

먼저 증거를 확인한다.
- workflow_dispatch 성공 로그
- 실제 신규 콘텐츠 1건의 published 추가
- 허용 경로만 포함한 master 자동 커밋
- npm test, npm run check, npm run build 성공
- Cloudflare 새 Production 빌드와 운영 URL 반영
- YOUTUBE_API_KEY와 branch protection/ruleset 준비

하나라도 확인되지 않으면 schedule을 추가하지 말고 남은 조건을 보고한다.

모두 확인되면 기존 workflow_dispatch를 유지하면서 다음 schedule만 추가한다.

on:
  schedule:
    - cron: "17 * * * *"
  workflow_dispatch:

매시간 실행이므로 timezone은 넣지 않는다. 관련 테스트와 문서를 갱신하고, 별도 커밋으로 schedule 변경만 명확하게 검토할 수 있게 한다.

반영 후 확인:
- 기본 브랜치에 workflow 파일 존재
- 다음 17분 예약 실행 발생
- 변경 0건 정상 종료
- 중복 실행 방지
- 45일 keepalive 테스트 유지
- 월 1회 Actions 활성 상태 점검 절차 문서화

실행하지 않은 예약 실행이나 운영 검증을 완료했다고 보고하지 않는다.
```

## 3차 프롬프트: 승인된 네이버 매물 원본 경로 확보 후

```text
외부 콘텐츠 자동 동기화와 분리하여 네이버 공개 매물 스냅샷 자동화를 검토해줘.

먼저 운영자가 제공한 중개업무 프로그램의 공식 API·CSV·export 문서와 자동 사용 권한을 확인한다. 네이버 부동산 웹페이지 크롤링, 내부 API 역공학, 로그인 세션 자동화, 접근 제한 우회는 하지 않는다.

src/data/naver-listings.json과 content-validation.mjs의 기존 검증을 유지하면서 다음을 설계한다.
1. 승인 원본과 공개 JSON의 필드 매핑
2. 누락·변환 불가능 필드
3. 신규·변경·종료 diff 정책
4. 삭제 대신 ended 또는 확인 필요 처리
5. 중복 매물번호와 URL 일치 검증
6. 확인일 갱신 규칙
7. 비공개 호수·고객·소유자·내부 메모 유입 방지
8. dry-run과 테스트
9. 핵심 문서와 운영 가이드 동기화

공식 원본 경로와 사용 권한이 불확실하면 구현을 멈추고 결정 필요 항목으로 보고한다.
```
