> 위 %는 체크 항목 기준 개발 진행률이지 제품 완성도가 아니다. 항목마다 일의 크기가 다르다. 단계 0에 남은 것은 운영자 승인 관문(🔒)·실기기와 실사용 확인(👤)·PR diff 대조와 운영 반영 확인뿐이다.

세는 규칙:

- 3 ~ 8장(단계 절) 안의 체크 항목만 센다. 1·2·9장, 코드 블록 안, 이 표 안의 줄은 세지 않는다.
- `- [x]`는 완료다. `- [ ]` 가운데 `🔒`(운영자 승인 관문)나 `👤`(운영자 작업·실기기 확인처럼 사용자를 기다리는 항목)가 있으면 대기·막힘, 그 밖에 `⏳`가 있으면 진행 중, 나머지는 남음이다.
- 막대는 10칸이다. 채운 칸 수 = 반올림(완료 ÷ 전체 × 10), % = 반올림(완료 ÷ 전체 × 100). 항목이 0개인 단계는 0%로 적는다.
- 단계 5(8장)는 반복 작업 표라 체크 항목이 없다.
- 이 표는 손으로 고친다. `scripts/work-tools-progress.mjs`가 생기면 표식 사이를 그 스크립트가 다시 쓴다.

### 검토·시험 규칙(모든 단계 공통)

- 만든 세션은 자기 변경을 검토·시험하지 않는다. 각 단계의 "시험" 항목, 결과 비교, PR diff 대조는 만든 세션이 아닌 다른 세션(지금은 검토·시험 담당)이 한다.
- 시험 결과는 실행한 명령과 실제 통과·실패 수, 테스트 체크리스트 시험 ID로 적는다. 실행하지 않은 검사나 실기기 확인을 통과로 적지 않는다.
- 검토 지적은 만든 세션이 고치고, 같은 검토 세션이 다시 확인한 뒤에만 `[x]`로 바꾼다.
- 모든 PR은 테스트 체크리스트 TR-11(회귀 묶음)을 통과해야 한다.
