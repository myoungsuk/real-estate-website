## 1. 사용 방법

### 1.1 표기

| 표기 | 뜻 |
|---|---|
| 시험 ID | `T0-…` 단계 0, `T2-…` 단계 2, `T3-…` 단계 3, `T4-…` 단계 4, `TU-…` 화면(모든 단계 공통), `TP-…` 개인정보(모든 단계 공통), `TR-…` 회귀, `TD-…` 배포 후 확인 |
| 담당 | **검토·시험**(만든 세션이 아닌 시험 담당 세션, 2026-11-16 기준 날개-2), **운영자**(실기기·외부 계정), **배포**(배포 담당 세션, 2026-11-16 기준 날개-3). 역할과 세션의 짝은 협업 보드 "세션과 역할" 표를 따른다 |
| 결과 | `미실행` / `통과` / `실패(내용)` / `해당 없음(이유)`. 통과는 실제로 실행한 경우에만 적는다 |
| ⚠ 설계 수정 대기 | 2026-11-16 설계서 검토에서 고칠 곳으로 지적된 항목. 설계서 v0.2에서 고쳐진 9건은 v0.3에서 기대값을 확정했다. 지금 남은 항목은 없음(T4-42e는 설계서 수정으로 확정) |
| (자동) | `node --test` 단위 시험이나 Playwright로 자동화할 항목 |
| (수동) | 사람이 직접 확인할 항목 |

### 1.2 규칙

1. 자기가 만든 변경은 자기가 시험하지 않는다(협업 규칙 6). 구현 세션은 단위 시험 코드를 쓸 수 있지만, 이 표의 "결과" 칸은 검토·시험 담당이 직접 실행한 결과로만 채운다.
2. 결과에는 실행한 명령, 통과·실패 수, 실행 시각, 기준 커밋을 함께 적는다(11장 양식).
3. 실기기 항목은 운영자가 실제 기기에서 확인한 경우에만 통과로 적는다. 에뮬레이터·Playwright 결과는 실기기 통과로 적지 않는다.
4. 실패하면 그 자리에서 고치지 않는다. 실패 내용을 만든 세션에 넘기고, 고친 뒤 같은 시험을 다시 실행한다.
5. 운영 환경 시험은 가상 데이터로만 하고, 시험이 끝나면 가상 데이터를 지운 뒤 지운 결과를 기록한다.

### 1.3 시험 환경

| 환경 | 용도 | 준비 |
|---|---|---|
| 로컬 순수 함수 | 단계 0 계산·날짜·`.ics`·문구 | `npm test` |
| 로컬 Worker | 단계 2 ~ 4 API | `npx wrangler dev`(D1·R2 `--local`), 가짜 Access·가짜 OpenAI fetcher를 `options`로 주입(설계서 10.5절) |
| 로컬 화면 | 화면·가로 넘침·접근성 | `npm run build` 후 Playwright(기존 `e2e/` 방식) |
| 운영(가상 데이터) | 배포 후 확인 | Access 로그인한 운영자 브라우저 + 배포 담당의 Cloudflare 화면 확인 |
| 실기기 | 캘린더·문자 앱·사진 촬영·알림 | 운영자의 실제 Android(Chrome)·iPhone(Safari) |

### 1.4 가상 데이터 세트

시험용 데이터는 아래 표식 문자열을 넣어 만든다. 유출 검사(TP-01 ~ TP-06)에서 이 표식을 찾는다.

| 종류 | 값 |
|---|---|
| 유출 검사 표식 | `ZZTEST-7F3A` (손님 이름·메모·파일 설명에 넣는다) |
| 가상 손님 | `가상 손님 A ZZTEST-7F3A` ~ `가상 손님 E ZZTEST-7F3A`, 전화 `01000000001` ~ `01000000005` |
| 가상 물건 | `가상단지 101동` ~ `가상단지 105동` |
| 가상 주민등록번호 형태 | `900101-1000000`, `000101-3000000`(가림 시험 전용, 실제 번호가 아닌 형태만 맞춘 값) |
| 가상 계약서 표본 | 20장. 표준 계약서 양식에 가상 금액·날짜·가상 이름을 넣어 출력하고 휴대폰으로 촬영한다. 각 장의 정답(계약일·금액·중도금·잔금)을 표로 따로 둔다. 실제 계약서는 쓰지 않는다 |
| 가상 녹음 | 운영자가 가상 대화를 직접 읽어 녹음한 파일(1분, 10분, 25MB 근처, 25MB 초과 4종) |

- 기준 커밋·브랜치:

- 가상 데이터 정리: 지움 / 해당 없음
