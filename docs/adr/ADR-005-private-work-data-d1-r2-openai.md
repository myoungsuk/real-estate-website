# ADR-005: 비공개 업무 데이터는 같은 Worker의 D1·R2에 두고, AI는 Worker가 OpenAI를 직접 호출

| 항목 | 내용 |
|---|---|
| 상태 | 승인(2026-11-16) |
| 작성일 | 2026-11-16 |
| 범위 | 관리자 업무 도구(`/admin/work/`, `/api/admin/v1/work/*`)의 손님·계약 데이터 저장, 파일 보관, AI 처리 |
| 확장하는 결정 | ADR-004(Workers Static Assets와 관리 API를 같은 Worker로 운영) |
| 상세 설계 | `docs/리더스시티 행복한부동산 중개업무 도구 설계서.md` |

## 배경

운영자는 2026-11-16 중개날개와 같은 중개 업무 기능(손님 관리, 계약 일정, 계약서·녹음 정리, AI 인식)을 관리자 화면 안에 만들기로 했다. 이 기능은 손님 이름·연락처·계약 내용·통화 녹음 같은 비공개 개인정보를 다룬다.

지금 저장소의 원칙은 다음과 같다.

- 저장소는 GitHub 공개 저장소이고, 공개 승인된 정보만 둔다(`CLAUDE.md` 공개·비공개 데이터 경계).
- 관리자 저장은 GitHub JSON 커밋이며 DB가 없다.
- "비공개 데이터가 필요해지면 JSON 필드를 추가하지 말고 DB·권한·암호화·보유기간을 별도로 설계하고 승인받는다"(`CLAUDE.md`).

이 ADR은 그 "별도 설계"의 구조 결정이다.

## 결정

1. **비공개 업무 데이터는 Git에 넣지 않는다.** 저장소는 계속 공개로 두고 코드와 공개 콘텐츠만 둔다.
2. **같은 Worker(`leaders-city-happy-realty`)에 Cloudflare D1과 R2를 바인딩한다.** D1(`WORK_DB`)에는 손님·메모·거래·일정·감사 로그를, 비공개 R2 버킷(`WORK_FILES`)에는 사진·녹음·문서를 둔다. R2 공개 주소(퍼블릭 버킷, `r2.dev`, 사용자 도메인)는 만들지 않는다.
3. **API는 `/api/admin/v1/work/` 아래에 두고 ADR-004의 보호를 그대로 쓴다.** Cloudflare Access(허용 이메일 2개 + Email OTP), Worker의 JWT 재검증, Origin·CSRF 검사. 운영자 결정(2026-11-16 원문 "3. 2명 모두")대로 업무 도구도 허용 이메일 2개 모두에게 연다. 대신 보기·수정·삭제·내보내기·AI 호출마다 작업자 이메일을 D1 감사 로그에 남긴다.
4. **업무 도구 활성화는 GitHub 설정과 분리한다.** 별도 변수 `WORK_TOOLS_ENABLED`와 바인딩 존재 여부로 판단하고, 설정이 없으면 fail closed(503)한다.
5. **AI는 Worker가 OpenAI API를 SDK 없이 직접 `fetch`로 호출한다**(운영자 승인 원문 "1. 지금 Worker(JavaScript) + 직접 fetch (추천)"). 기존 `githubRequest(path, init, env, fetcher = fetch)`와 같은 모양으로 만들어 시험에서 바꿔 끼운다. 브라우저 직접 호출과 95번 서버(comibot) 경유 호출은 하지 않는다. 브라우저 쪽 라이브러리(얼굴 인식 등)는 이 결정의 대상이 아니며 따로 정한다.
6. **AI 모델은 작업별 설정값으로 두고, 기본은 `gpt-6.1-sol`, 계약서 두 번 읽기만 `gpt-6.1-sol` + `gpt-6-astra` 교차, 추론은 모두 최고(`max`)로 한다.** 모델 이름과 추론 수준은 코드에 박지 않고 설정값으로 둔다. 키는 comibot과 분리한 새 OpenAI 프로젝트의 키를 Cloudflare Secret에만 둔다. `store:false`, 생성 요청 재시도 0회, 메타데이터만 로그, 예산 상한을 지킨다.
   - 근거(2026-11-16 OpenAI 공식 모델·가격 문서): `gpt-6.1-sol`은 "Near-Astra performance for complex work at a lower cost", 입력 100만 토큰당 2달러·출력 10달러, 추론 low ~ max, 이미지 입력·구조화 출력 지원. `gpt-6-astra`는 "Our most capable model", 입력 10달러·출력 50달러. 출처: https://developers.openai.com/api/docs/models/gpt-6.1-sol , https://developers.openai.com/api/docs/models/gpt-6-astra , https://developers.openai.com/api/docs/pricing
   - 결정 경위: 09:43:23 운영자 원문 "…api 호출비용 상관없이 제일 성능이 좋게 나오도록 하는 모델이랑 추론 기능 썼으면 좋겠어"로 처음에는 최상위 모델(`gpt-6-astra`) 단일 안이었다. 10:54:38 "전부 6.1 Sol"은 9초 뒤 번복되어 적용하지 않았고, 10:54:47 "아니대 18번 추천대로하자"가 결정이다(보드 0절 18번 추천안). 추론 수준은 처음 결정 그대로 최고다.
   - 단계 4 착수 때 가상 계약서로 "Sol 두 번"과 "Sol + Astra 교차"의 정확도·시간·비용을 비교해 확정한다. 결과가 비슷하면 설정값만 바꿔 Sol 두 번으로 할 수 있다.
7. **긴 AI 처리는 휴대폰 연결과 떼어 놓는다.** 사진 인식·요약은 OpenAI background 모드 + 브라우저 폴링 + 매분 Cron 보조 폴링으로 결과를 D1에 받아 둔다. 음성 변환은 보관이 없어 다시 받을 수 없으므로 작업으로 등록하고 매분 Cron이 처리한다.
8. **주민등록번호는 저장하지 않는다.** 계약서 사진은 올리기 전에 브라우저에서 가린다. 이 앱은 법정 서류 보존 수단이 아니라 업무용 가린 사본만 두는 것을 추천안으로 하고, 최종 선택은 결정 대기(DEC-WT-08)로 둔다.

## 이유

- 공개 저장소의 경계를 바꾸지 않고 비공개 데이터를 분리할 수 있다. Git 이력에는 지울 수 없는 기록이 남지만 D1·R2는 지울 수 있다.
- 지금 운영 중인 Worker·Access·CSRF·배포 구조를 그대로 쓰므로 새 서버·새 도메인·새 인증이 필요 없다(ADR-004가 이미 "향후 R2·배포 이력 기능을 같은 Worker에 단계적으로 추가"를 예상했다).
- D1과 R2는 사무소 한 곳·계정 2개 규모에서 무료 범위 안에 머물 가능성이 높다(**추정**, 설계서 15장).
- SDK 없이 `fetch`로 부르면 Worker 번들이 커지지 않고, 기존 시험 방식(가짜 fetcher)을 그대로 쓸 수 있다.
- 모델 이름을 작업별 설정값으로 두면 더 좋은 모델이 나오거나 비교 결과가 바뀌어도 코드 변경 없이 바꿀 수 있다.
- 기본 모델을 `gpt-6.1-sol`로 하면 AI 비용이 Astra 단일 안의 약 1/3로 줄고(기획서 11.3절 가정 기준, 음성 변환 제외 비교: 상한 약 50.7 대 165달러, 평균 약 17.7 대 60달러. 계약서 2회째가 Astra로 남아 1/5까지는 줄지 않음, **추정**), 날짜·금액이 걸린 계약서만 Astra를 교차로 섞어 서로 다른 모델의 오류가 겹칠 가능성을 줄인다.

## 검토한 대안

### 저장소를 private으로 바꾸고 JSON·사진을 Git에 저장

- 장점: 지금 GitHub 저장 방식을 그대로 쓴다.
- 포기 이유: 개인정보가 Git 이력에 영구히 남아 삭제 요청을 처리하기 어렵다. 공개 사이트의 Workers Builds·검색 등록·IndexNow 흐름이 공개 저장소를 전제로 한다. 협업자·Actions·포크 권한을 모두 다시 점검해야 한다.

### 새 private 저장소에 데이터 저장

- 장점: 공개 저장소와 분리된다.
- 포기 이유: 여전히 Git 이력 삭제 문제가 있고, 검색·동시 수정·파일 크기 처리에 Git이 맞지 않는다. 토큰과 저장소가 하나 더 늘어난다.

### 중개날개 같은 기존 서비스 구독

- 장점: 바로 쓸 수 있고 유지보수가 없다.
- 포기 이유: 운영자가 기능을 직접 만들기로 결정했다. 데이터가 외부 서비스에 있고, 우리 홈페이지·공개 매물과 연결할 수 없다. 비교는 기획서 3.4절.

### 별도 서버(95번 서버) 또는 C#·.NET 서비스

- 장점: comibot 코드(공식 OpenAI .NET SDK)를 재사용할 수 있고, 상주 프로세스라 긴 작업·카운터를 쉽게 둔다.
- 포기 이유: 외부에 열린 서버와 인증·백업·보안 패치를 따로 운영해야 한다. 사무소 서버 장애가 업무 도구 장애가 된다. 운영자가 "Worker(JavaScript) + 직접 fetch"를 승인했다. AI 성능은 언어가 아니라 모델·입력 품질·요청 설계가 정한다.

### 별도 업무 도구 Worker

- 장점: 공개 사이트와 장애·권한 경계를 더 강하게 나눈다.
- 포기 이유: ADR-004와 같은 이유로 프로젝트·Secret·배포 관리가 늘어난다. 같은 Worker 안에서도 경로·활성화 변수·바인딩으로 경계를 나눌 수 있다. 사용량이 커지거나 장애 분리가 필요해지면 다시 검토한다.

### 다른 클라우드 DB(외부 관리형 Postgres 등)

- 포기 이유: Worker 밖으로 연결·인증 정보를 하나 더 두게 되고 비용이 생긴다. D1은 같은 계정 바인딩이라 별도 자격 증명이 필요 없다.

## 결과·영향

긍정:

- 공개 저장소 원칙이 유지된다.
- 기존 인증·CSRF·배포 구조를 재사용한다.
- 손님 자료를 실제로 지울 수 있다.

부정·주의:

- **처음으로 운영 데이터베이스가 생긴다.** 마이그레이션, 백업(D1 Time Travel: 무료 7일, 유료 30일), 복원 훈련, 보유기간·파기 운영이 필요하다.
- **삭제 뒤에도 Time Travel 기간 동안 복원 가능한 상태로 남는다.** 처리방침에 적어야 한다.
- **국외 이전**: Cloudflare(위치 힌트 `apac`은 보장 아님)와 OpenAI(미국)로 개인정보가 저장·처리될 수 있다. 처리방침 수정이 운영 시작 조건이다.
- **두 이메일 계정의 보안에 손님 자료가 달려 있다.** Email OTP 로그인이라 한쪽 메일 계정이 뚫리면 손님 자료가 노출된다. 두 계정 모두 2단계 인증을 필수로 한다.
- **Workers 무료 플랜 CPU 10ms 한도**가 AI 단계(사진 처리, 음성 변환 Cron)에서 부족하다. 운영자가 Workers Paid(월 5달러)를 승인했다(DEC-WT-12, 2026-11-16 "2. 5달러로 해"). 전환 시점은 단계 2 CPU 실측 또는 늦어도 단계 4 전이다.
- **관리자 대면 녹음 화면 한 곳에 마이크를 허용한다**(DEC-WT-14, 2026-11-16 "4. 어 녹음하게 해"). `public/_headers`의 전역 `Permissions-Policy: microphone=()`를 `/admin/work/record/` 경로에서만 떼고 `microphone=(self)`를 포함한 전체 값을 다시 적는다. 전화 통화는 웹에서 녹음할 수 없어 파일 업로드를 유지한다.
- `wrangler.jsonc`에 D1·R2·Cron 바인딩이 추가되어 전역 배포 설정이 바뀐다. 배포 실수는 운영 사이트 전체에 영향을 준다.
- 관리자시스템 설계서 5.2 "제외 범위"(CRM, 계약 관리, 계약서 업로드 등)가 업무 도구 범위로 옮겨진다. 신분증 업로드는 계속 제외한다.

## 보안 영향

- Access 정책과 Worker JWT 재검증을 모두 통과해야 한다(ADR-004와 같음).
- 업무 도구 API는 `WORK_TOOLS_ENABLED`, D1·R2 바인딩, CSRF Secret, 허용 출처 설정이 모두 있어야 동작하고, 하나라도 없으면 503으로 막힌다.
- 감사 기록을 쓰지 못하면 손님 자료를 돌려주지 않는다.
- Worker 로그에는 이메일 원문·손님 이름·본문을 남기지 않는다. 작업자 이메일 원문은 D1 감사 로그에만 있다.
- 파일은 Worker가 Access 검증 뒤에만 스트림으로 내려준다. 객체 키에 개인정보를 넣지 않는다.
- OpenAI 키는 Secret에만 둔다. 브라우저는 OpenAI 주소에 연결하지 않는다(CSP `connect-src 'self'` 유지).
- 마이크는 대면 녹음 화면(`/admin/work/record/`) 한 경로에서만 허용한다. `_headers`는 같은 헤더를 합치므로 그 경로에서 전역 값을 `!`로 떼고 전체 값을 다시 적으며, 응답에 Permissions-Policy가 1개인지 시험한다.
- 캘린더 구독 주소를 고르면 Access 밖 공개 경로(`/api/calendar/*`)가 하나 생긴다. 256비트 토큰, 해시 저장, 취소, 이름 미포함 제목, WAF 속도 제한으로 보호한다.

## 검증

- GitHub 설정 없이 업무 도구가 동작하고, 업무 도구 설정이 없으면 503인지
- Access 없음·위조·만료·허용 목록 밖 이메일 거부, 허용 이메일 2개 모두 통과
- 보기·수정·삭제·내보내기·AI 호출마다 감사 로그에 JWT 이메일이 남는지
- R2 객체를 직접 주소로 열 수 없는지
- Git·`dist/`·deployment marker·Worker 로그에 가상 손님 데이터가 0건인지
- 손님 삭제 시 D1 행과 R2 객체가 실제로 사라지는지
- OpenAI 생성 요청이 자동 재시도되지 않는지(가짜 fetcher 시험)
- `npx wrangler deploy --dry-run` 번들에 Secret 문자열이 없는지
- D1 Time Travel 복원 훈련 1회

## 롤백

1. Cloudflare Production 변수 `WORK_TOOLS_ENABLED=false`(또는 `WORK_AI_ENABLED=false`)로 즉시 기능을 막는다. 데이터는 그대로 남는다.
2. 코드 문제면 직전 정상 Cloudflare 배포로 되돌리고 `git revert`한다.
3. 구조 자체를 걷어내면 `wrangler.jsonc`에서 D1·R2·Cron 바인딩과 `/api/calendar/*`를 빼고 `worker/work-*.mjs`를 제거해 재배포한다.
4. D1·R2 데이터 삭제는 운영자에게 전체 내보내기를 넘긴 뒤, 운영자 승인을 받아 별도 작업으로 한다. 삭제 후에도 D1 Time Travel 기간 동안은 복원 가능하다는 점을 기록한다.
5. OpenAI 프로젝트 키를 폐기한다.
