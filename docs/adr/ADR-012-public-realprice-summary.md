1. 실거래 요약(단지 페이지 칸 + 홈 한 줄)
2. 홈 매물 줄 '최근 7일 등록 n건'(PR #174, 이 ADR과 무관)
3. 거래 완료 소식
4. 동네 소식(홈페이지 안에서 읽는 글) — 같은 날 14:44:50 하지 않기로 했다(결정 12)

## 결정

1. **실거래 요약을 공개한다.** 범위는 공개(`published`) 단지 가운데 연결표에 넣은 단지(지금 3곳: `leaders-city-4`·`leaders-city-5`·`sinheung-sk-view`), **매매만**, **요약만**이다. 전월세·분양권과 그 밖의 단지, 원자료 전체는 공개하지 않는다. 3곳은 지금 값이지 고정 허용값이 아니다.
2. **자료 길은 '라'다.** Worker에 요약 JSON만 돌려주는 주소를 하나 두고, GitHub Action이 하루 한 번 받아 검사한 뒤 파일 하나를 커밋한다.
   - Worker 주소(가칭 `/api/public-data/realprice-summary`): `Authorization` 헤더의 토큰을 Worker Secret과 대조한다. 켜기 값이 없거나 토큰이 틀리면 D1을 읽지 않고 모두 같은 404를 준다. 토큰은 주소에 싣지 않는다.
   - 워크플로(가칭 `sync-realprice-summary.yml`): 예약 실행(예: 매일 06:50 KST) + 수동 실행. 읽기 job(`contents: read`)이 받아 검사하고, 쓰기 job(`contents: write`)이 파일 1개만 커밋한다. 다른 동기화와 같은 `concurrency` 묶음에 넣고, 실패하면 이슈를 연다(부동산뱅크 받기와 같은 방식).
   - 배포 표식(`deployment-marker.json`)에 새 범위 `realprice`를 더해 커밋 뒤 운영 반영을 확인한다.
3. **요약 파일은 `src/data/realprice-public.json`(가칭) 하나다.** `src/data/work/` 아래에 두지 않는다. 처음 값은 빈 목록이고 가짜 샘플을 넣지 않는다.
   - 넣는 칸: 공개 단지 slug, 계약 연월일, 전용면적, 층, 금액, 달별 흐름선 값, 최근 7일 새 신고 건수, 만든 시각 `generatedAt`, 자료 기준 시각
   - 넣지 않는 칸: 동 번호(`apt_dong`), 지번, 거래 번호(`trade_key`), 단지 번호(`apt_seq`), 중개·직거래 구분, `extra_json`, 공공 API가 준 단지 이름 글자(이름은 `complexes.json`에서 읽는다)
4. **단지 칸은 매매만, 층은 보이고 동 번호는 보이지 않는다.** 전용면적별로 최근 3 ~ 5건과 12개월 흐름선을 싣는다(건수와 흐름선을 그리지 않는 기준은 화면 시안 때 정한다). "이번 달 거래" 같은 기간 문구 대신 "최근 n건"을 계약일과 함께 보인다.
5. **홈 실거래 줄에는 금액을 싣지 않는다.** "최근 7일 새로 신고된 거래 n건" 꼴로 건수만 보이고 단지 페이지로 보낸다. 세는 기준은 `first_seen_at` 최근 7일이고 처음 한꺼번에 받은 자료(`is_backfill`)는 뺀다. 0건이면 줄을 그리지 않는다.
6. **공개 단지 slug → `apt_seq` 연결은 코드의 고정 표로 둔다.** 관리자 화면 '관심 단지'(`rt_watch_complexes`)에 묶지 않는다. 사람이 화면에서 관심 단지를 바꿔도 공개 칸이 따라 바뀌지 않게 하기 위해서다. 시험이 이 표를 `complexes.json`의 공개 단지와 대조한다.
7. **검사 함수 하나를 두 곳에서 쓴다.** 내보내기 전(Worker·Action)과 빌드 전(`scripts/content-validation.mjs`)이다.
   - 금지 칸이 있거나 허용 칸 목록 밖의 키가 있으면 **빌드 실패**(공개 사고를 막는 쪽)
   - 그 밖의 모양 오류(범위 밖 숫자, 건수 상한 초과 등)는 **칸만 숨기고 경고**로 남긴다. 자동으로 들어온 파일 하나가 홈페이지 전체 배포를 멈추지 않게 하기 위해서다.
   - 지금 `findSensitiveStrings()`는 휴대전화·이메일·"숫자 + 호"만 잡으므로 이 파일의 칸 검사는 새로 쓴다.
8. **낡은 숫자를 세 겹으로 막는다.**
   - 칸에 늘 기준일과 출처를 글자로 적는다(스크립트가 꺼진 환경과 검색 로봇에도 남는 유일한 막이).
   - 화면을 연 때 `generatedAt`에서 일정 시간(추천 72시간, 정할 값)이 넘었으면 칸을 숨긴다. 서버를 부르지 않는다(관리자 대시보드 `bankSyncState`와 같은 방식).
   - 관리자 대시보드 '실거래·매물' 칸에 멈춤 줄을 더하고, 워크플로 실패 때 이슈를 연다.
9. **해제된 거래는 요약에서 뺀다**(추천, 화면 시안 때 확정). 해제 신고는 늦게 붙을 수 있으므로 "신고·해제에 따라 바뀔 수 있음"을 칸 문구에 넣는다.
10. **매물 광고처럼 보이지 않게 한다.** 칸 제목에 "실거래(국토교통부 신고 자료)"를 넣고 "매물이 아닙니다"를 한 줄로 적는다. 실거래 줄마다 문의 단추를 붙이지 않는다. '신고가'·'급등' 같은 딱지를 공개 화면에 쓰지 않는다.
11. **거래 완료 소식**은 대표가 건마다 직접 넣는 새 공개 JSON으로만 싣는다. D1의 손님·거래 자료에서 자동으로 끌어오는 길을 두지 않는다. 범위는 대전 동구 전역이고 단지 이름은 자유 입력이다. 금액·동·층·호수·날짜는 싣지 않고, 단지 실거래 칸과 같은 화면에 두지 않으며, 매매는 실거래 자료에 나타나고 일정 기간이 지난 뒤에 올리고, 거래가 드문 단지는 동네 이름으로 올린다. '드문 단지'와 '일정 기간'의 숫자는 따로 승인받는다(설계 문서).
12. **동네 소식은 하지 않는다**(2026-11-25 14:44:50 사용자 결정 "동네 소식은 하지말자 네이버 블로그 있으니깐"). 14:16:45에는 머리 메뉴 '매물' 다음에 두고 단지 소개 글만 싣기로 했으나, 네이버 블로그와 겹친다는 까닭으로 접었다. 글은 지금처럼 네이버 블로그에 올리고 홈페이지는 그 글의 링크만 보인다(`external-links.json`, 바뀌는 것 없음). 2026-11-25 15:06:35 "전부 추천대로"로 네이버 블로그 카드에 글 앞부분 요약과 분류 딱지를 더 보이기로 했다(글 전체는 싣지 않음, 시스템설계서 11.1절). 메뉴 '블로그'를 '네이버 블로그'로 바꾼 것(PR #175)은 이미 운영에 반영됐고, 되돌릴지는 따로 정한다. 글에 "AI 도구를 썼다"는 문장을 넣지 않는다는 결정(14:04:08)은 홈페이지에 실을 글이 없어 쓸 곳이 없다.
13. **켜는 순서**는 업무 도구와 같다. 서버는 꺼진 채로 병합해 시험만 돌리고, 화면은 빈 파일 상태로 병합해 운영에 아무것도 보이지 않게 둔 뒤, Secret을 등록해 한 번에 켠다. 공개 FAQ·이용약관·`llms.txt` 문장은 화면이 보이는 PR에서 함께 바꾼다(그 전에 바꾸면 문장이 화면과 어긋난다).

## 이유

- 길 '라'에서 GitHub에 놓이는 토큰이 열 수 있는 것은 어차피 공개할 요약뿐이다. 손님 자료 D1에 닿는 열쇠가 Cloudflare 밖에 놓이지 않는다.
- Cron이 저장소 쓰기 토큰을 쓰지 않는다. 커밋은 지금 세 번 만든 동기화 워크플로와 같은 모양(읽기 job 검증 → 쓰기 job 커밋)이라 실패 알림·push 충돌 막이·배포 확인을 그대로 가져온다.
- `GITHUB_TOKEN` 커밋이라 매일 CI·Lighthouse·IndexNow가 돌지 않는다.
- 정적 HTML에 숫자가 들어가므로 검색 로봇이 읽는다(화면에서 API를 부르는 길은 이 효과가 없다).
- 공개 FAQ와 `complexes-overview.json`의 "가격은 날짜와 조건을 붙여 봅니다(계약일·면적·층·방향·옵션·해제 여부)"는 층을 함께 보라고 말한다. 층을 빼면 이 문장과 어긋난다. 동 번호는 등기를 마친 거래에만 값이 있고 관리자 홍보물에도 넣지 않기로 했다(업무 도구 설계서 DEC-WT-22).
- 홈 줄에 금액을 두지 않으면 홈에 있는 거래 완료 소식과 금액이 나란히 놓이지 않는다.

## 검토한 대안

### (가) Worker Cron이 GitHub에 직접 커밋

- 장점: 새 주소·새 워크플로가 없다.
- 포기 이유: Cron이 저장소 쓰기 토큰을 쓴다. 매일 CI·Lighthouse·IndexNow가 돌고, 다른 동기화와의 push 충돌을 시각으로만 피한다.

### (나) GitHub Action이 Cloudflare 토큰으로 D1을 직접 읽음

- 장점: Worker를 고치지 않는다.
- 포기 이유: 손님 자료가 든 D1을 읽을 수 있는 토큰이 GitHub에 놓인다. 처리방침 검토도 필요해진다.

### (다) 공개 화면이 Worker의 공개 API를 부름

- 장점: 낡은 숫자가 남지 않는다.
- 포기 이유: 공개 홈페이지에 DB를 두지 않는다는 원칙까지 바꿔야 하고, 정적 HTML에 숫자가 없어 검색 효과가 없다.

### (마) 이 PC의 작업 스케줄러가 받아 커밋

- 포기 이유: PC가 꺼지면 멈추고 Cloudflare 토큰이 PC에 놓인다.

## 결과·영향

- Access 밖에서 Worker가 먼저 받는 경로가 캘린더 구독에 이어 2개가 된다(`wrangler.jsonc`의 `assets.run_worker_first`, 전역 설정 변경).
- 비밀값이 한 쌍 는다(Worker Secret 토큰·켜기 값, GitHub Secret 토큰).
- 워크플로가 하나 늘고, 배포 표식에 범위 `realprice`가 하나 는다.
- `scripts/indexnow.mjs`는 표에 없는 `src/data/` 파일이 바뀌면 사이트맵 전체를 알린다. 이 파일은 `GITHUB_TOKEN` 커밋이라 IndexNow가 돌지 않지만, 사람이 손으로 고쳐 올릴 때를 위해 표에 단지 페이지 주소를 적는다.
- 홈 실거래 줄은 0건인 주가 흔하다(3곳을 합쳐도 매매가 많지 않다). 줄이 없는 홈이 기본 모습이므로 화면 시안은 줄이 없는 홈도 함께 본다.
- 리더스시티 5블록은 2026-09-21 뒤로 매매 신고가 없고 최근 12개월 매매가 면적대마다 0 ~ 3건이다. 단지 칸은 한두 줄이고 흐름선은 점 몇 개이거나 비어 보인다. 4블록 84㎡대도 12개월 6건이다.
- GitHub 예약 실행은 수십 분 늦을 수 있고, 저장소가 오래 조용하면 꺼진다(지금 45일 keepalive가 있다).
- 함께 고칠 문서: `CLAUDE.md`(핵심 모듈 실거래 줄, 공개·비공개 데이터 경계, Cloudflare 배포, 환경변수), 서비스기획서, 시스템설계서, 개발진행체크리스트, 업무 도구 기획서 RISK-26·10.8절, 업무 도구 설계서 22장, 업무 도구 진행·테스트 체크리스트 7.6.1 완료 기준, ADR-011(가리킴 한 줄), ADR-004(가리킴 한 줄), `CONTENT_GUIDE.md`·`CLOUDFLARE_DEPLOY.md`·`SEARCH_REGISTRATION.md`. **지금 형으로 적힌 원칙 문장은 그 코드를 넣는 PR에서 바꾼다.**

## 보안 영향

- 새 주소는 요약만 만든다. 손님·거래·메모·파일 표를 읽는 코드를 넣지 않는다.
- 켜기 값이 없거나 토큰이 틀리면 D1을 읽지 않으므로, 토큰 없는 요청으로 D1 읽기 과금이 늘지 않는다. 캘린더 구독과 같은 속도 제한 규칙을 검토한다.
- 공개 저장소의 Git 이력은 지울 수 없다. 그래서 금지 칸(동·지번·거래 번호·단지 번호)은 커밋 전 검사와 빌드 전 검사 두 곳에서 막는다.
- `CLAUDE.md` '공개·비공개 데이터 경계'의 "비공개 동·층 정보"는 매물 광고에 대한 문장이다. 실거래 요약은 "공공 신고 자료의 층까지, 동 번호는 제외"를 따로 적어 두 문장이 섞이지 않게 한다.
- 거래 완료 소식은 화면에 날짜를 보이지 않아도 **공개 저장소의 커밋 시각**이 "언제 올렸는지"를 남긴다. 실리는 내용 자체가 금액·층을 짐작할 수 없는 수준이어야 하는 까닭이다(설계 문서 5절).

## 검증

- 빈 파일이면 단지 칸·홈 줄이 그려지지 않는다. 가짜 고정 자료를 넣으면 그려진다(E2E·Lighthouse는 실제 숫자에 기대지 않는다).
- 금지 칸이 든 파일은 내보내기 검사와 빌드 전 검사에서 모두 거절된다.
- 켜기 값 없음·토큰 없음·토큰 틀림은 같은 404이고 D1 읽기가 0번이다.
- 연결표의 slug가 모두 `complexes.json`의 공개 단지다.
- 빌드 산출물에 허용 칸 밖의 실거래 자료(동·지번·거래 번호·단지 번호)가 0건이다(업무 도구 7.6.1 완료 기준을 이 문장으로 바꾼다).

## 롤백

1. Worker Secret 켜기 값을 지운다(주소가 404가 되고 워크플로는 실패 이슈를 연다).
2. 워크플로를 끄고 요약 파일을 빈 목록으로 되돌린다(칸·홈 줄이 사라진다).
3. 공개 FAQ·이용약관·`llms.txt` 문장을 되돌린다.
4. 이미 커밋된 요약은 Git 이력에 남는다. 공공 자료의 허용 칸뿐이므로 지우지 않는다.

## 확인하지 않은 것

- 국토교통부 실거래가 자료의 출처 표시 의무(업무 도구 기획서 10.8절에 '추가 확인 필요'로 남아 있음). 의무와 상관없이 출처와 기준일을 적는다.
- 실거래 요약이 표시·광고 규정(공인중개사법 제18조의2)의 대상인지. '의뢰받은 중개대상물'의 광고가 아니라고 보지만 법률 판단이 아니다.
- 공인중개사법 시행령 제17조의2 본문, 부동산 거래신고 등에 관한 법률의 현행 조문(매매 신고 기한 30일은 검색 요약으로만 확인, 주택 임대차 신고 조문은 확인하지 못함).
- 흐름선을 그리지 않는 기준(관리자 화면은 점 2개 미만이면 그리지 않는다. 공개 화면 기준은 시안 때 정한다).
